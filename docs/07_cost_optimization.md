# 비용 최적화

## 적용된 기능: Prompt Caching

### 개념

Anthropic API 호출 시 시스템 프롬프트에 `cache_control` 을 지정하면,  
동일한 내용의 프롬프트 토큰을 캐시에 저장하고 이후 요청에서 재사용합니다.

- **캐시 히트 시**: 해당 토큰을 **원가의 10%** 만 과금 → 최대 90% 절감
- **캐시 유효 시간**: 5분 (ephemeral)
- **최소 캐시 크기**: 1,024 토큰 (Claude Sonnet 기준)

### 적용 코드

```javascript
// anthropic-beta 헤더 추가
headers: {
  'anthropic-beta': 'prompt-caching-2024-07-31',
  // ...
}

// system을 배열 형식으로 변경하고 cache_control 지정
system: [{
  type: 'text',
  text: systemPrompt,
  cache_control: { type: 'ephemeral' }
}]
```

### 이 앱에서 캐시 히트가 발생하는 상황

| 상황 | 캐시 히트 여부 | 설명 |
|---|---|---|
| 렌더링 오류 → 자동 수정 재시도 | ✅ 히트 | fixMermaidCode 시스템 프롬프트 동일 |
| 같은 유형을 다시 생성 | ✅ 히트 | generateDiagram 시스템 프롬프트 동일 |
| 분석 → 재분석 (같은 세션) | ✅ 히트 | analyzeText 시스템 프롬프트 동일 |
| 다른 유형 생성 | ❌ 미스 | 다이어그램별 프롬프트가 다름 |
| 다른 사용자 (다른 API 키) | ❌ 미스 | 캐시는 API 키 단위로 격리 |

## 미적용 기능: Batch API

### 개념

요청을 즉시 처리하지 않고 큐에 쌓아두면 24시간 내에 처리해주는 방식.  
**50% 할인** 적용.

### 이 앱에 적용하지 않은 이유

이 앱은 사용자가 결과를 즉시 확인하는 **실시간 인터랙티브** 앱입니다.  
Batch API는 "1만 개 문서를 밤새 분석"과 같은 **대량 비동기 파이프라인**에 적합합니다.

---

## 두 기능 조합의 실제 효과 (참고)

"최대 95% 절감"이 실제로 실현되는 시나리오:

```
[적합한 케이스]
- 수만 줄짜리 계약서/코드베이스를 컨텍스트에 올리고
- 동일 문서에 수백 개의 질문을 반복 처리 (Batch API + Caching 조합)

[이 앱의 케이스]
- 시스템 프롬프트: 수백 토큰 (캐시 최소치 경계)
- 사용자별 1회성 호출
→ 절감 효과 존재하지만 95%에는 미치지 못함
```

## Claude vs OpenAI 비용 비교

| 항목 | Claude Sonnet | GPT-4o |
|---|---|---|
| 기본 입력 토큰 단가 | 중간 | 중간 |
| Prompt Caching 할인 | 최대 90% | 자동 (별도 설정 불필요) |
| Batch API 할인 | 50% | 50% |
| 캐싱+배치 조합 | 최대 95% | 조합 가능 |

순수 토큰 단가만으로는 모델마다 다르지만,  
Claude는 Prompt Caching을 명시적으로 제어할 수 있어 반복 호출이 많은 환경에서 유리합니다.
